# dsh-wechat-usb 2.0（多会话）

> 相对 `v0.3.1` 的完整说明。v0.3.1 的行为被原样保留在「单会话」模式里，随时可以切回去。

## 一句话

1.0/0.3 是**一个人蹲在一个群里**；2.0 是**自己在聊天列表里巡场**：谁有新消息就进谁的会话，看一眼决定接不接，接就开一条讨论串。

---

## 1. 两种模式，一个开关

设置页「会话模式」左右标签切换（配置项 `multi.enabled`）。

| | 单会话（v0.3.1） | 多会话 |
|---|---|---|
| 待在哪 | 死盯 `whitelistChats[0]` | 停在聊天列表，按未读巡场 |
| 群里没 @ | 到点（`noMentionIntervalMin`）主动搭一句 | **不搭**，只在没人找她时另走「主动搭话」 |
| 讨论串续命 | 群里任何新消息都算 | 只算 @ / 引用她 / 她自己说话 |
| 私聊 | 不单独处理 | 进门即开串、必回 |
| 主动搭话的入口 | 就地搭一句 | 自己挑一个会话过去开新话题 |

**单会话模式就是 v0.3.1 的行为**，切过去可以当作回滚。

---

## 2. 巡场链路（多会话）

```
定时器（列表轮 15s / 慢轮 30s / 快轮 4s）
  ↓
页面探针（30ms，纯像素）→ 不是列表就回列表
  ↓
扫列表（1 张截图 → OCR → 红点数像素）→ 会话名 / 未读 / 预览
  ↓
准入过滤（私聊放行；群要白名单）
  ↓
选候选（未读>0 且预览变了且不在冷却；@提示 > 私聊 > 群）
  ↓
进入（主：搜索，位置无关；兜底：点行）
  ↓
读屏 → 差分 → 时间去重 → 判官
  ↓
开串 / 续命 / 只 ack
```

详见 `docs/architecture.md` 与 `docs/entry-flow.png`。

## 3. 这一版解决的老问题

| 问题 | 现在的做法 |
|---|---|
| 点行点错（截图到点击隔 2 秒，列表被顶动） | **搜索进入**：不依赖行位置 |
| 判断"现在是不是列表"要 OCR 1.5 秒 | **像素探针** 30ms（白底 / 四簇 tab / 返回箭头） |
| 同一时刻反复截图 | 一张图多处裁切复用，一次进出 5~7 张降到 3~4 张 |
| 同一张动图每帧都算新消息 | 识图描述按「谁：〔图片〕」归一；新增**看帧判官**（两帧给 4B 判有没有新消息） |
| 4B 没有上一帧的记忆 | OCR 时把**上一帧的输出**一起给她对比 |
| 同一条 @ 被 OCR 读歪后又被当成新 @ | 相似度比对（如"升天"→"升大"仍算同一条） |
| 发言之前的旧消息又被回一遍 | **时间优先去重**：发言那一刻屏幕上的行，之后再现不算新消息 |
| 群被当成私聊 → 没人 @ 也回话 | 判群三层线索：标题成员数 → 正文人名数 → `data/chats.json` 记忆 |
| 叫醒后不回（空转） | 用真实发送时间判定，连续 2 次空转 → 该群静默 5 分钟 |

## 4. 主动搭话（重做）

**定义**：不是"接话"，是**主动开一个新话题**。

```
触发：没有活着的讨论串
      且 距上一条串结束 ≥ proactiveIntervalMin（默认 30 分钟）
      且 本小时主动次数 < proactiveMaxPerHour（默认 3）
  ↓
把候选清单交给模型（白名单群 + 所有私聊，去掉黑名单）
  ↓
模型自己挑一个 → wechat_open 进去 → 开新话题
（不经过判官：开新话题不需要"值不值得接"）
```

配置：

| 项 | 默认 | 说明 |
|---|---|---|
| `proactiveInGroups` | 关 | 主动搭话总开关 |
| `proactiveIntervalMin` | 30 | 间隔，从**上一条串结束**算 |
| `proactiveMaxPerHour` | 3 | 每小时上限 |
| `proactiveChats` | 空 | 候选会话；空则用 `whitelistChats` |
| `proactiveDmBlacklist` | 空 | 不搭话的私聊 |

> 多会话模式下**不存在"串外搭一句"**：她说的每句话都必须在某条讨论串里。

## 5. 讨论串

| 触发 | 什么时候开 | 续命条件（多会话） |
|---|---|---|
| `mention` | 有人 @ 她 | 又被 @ / 引用她的话 |
| `dm` | 进私聊就开 | 对方每说一句 |
| `self` | 她自己开的头 | 有人说的话沾到她 / 她继续说话 |

- 群串闲置 `dmThreadTtlMin`？不——群的闲置 TTL 是 `threadTtlMin`（默认 10 分钟），私聊另有 `dmThreadTtlMin`（默认 5 分钟）
- 一条串最多活 `threadMaxMin`（0 = 不限）
- 同一串 10 分钟内最多叫醒 6 次；私聊不限

---

## 6. 设置页

- **运行状态**（每 5 秒刷新）：在不在串里、串 id/触发原因/年龄、主动搭话还差几分钟、本小时用量、候选、上次扫描/唤醒/发送、保持中剩余秒数、冷却与退避
- **回复延迟**拆两段：
  - 检测延迟 = 消息出现 → 决定叫她（快轮间隔 + OCR + 攒批窗口）
  - 回复耗时 = 叫醒 → 消息真的发出去
- 会话模式：左右标签切换

## 7. 数据文件

| 文件 | 内容 |
|---|---|
| `data/threads.json` | 讨论串 |
| `data/proactive.json` | 每个会话上次主动搭话的时间 |
| `data/latency.json` | 最近 30 次延迟 |
| `data/chats.json` | 哪些会话是群、哪些是私聊 |
| `data/last-send.json` | 最近发出去的消息（判断"真回了没"） |
| `data/inbox/index.json` | 待处理消息 |
| `data/shots/` | 截图（`head-` / `list-` / `title-` / `poll-` / `open-`） |

## 8. 升级注意

1. **默认还是单会话**？不——2.0 默认多会话。要回 v0.3.1 就在设置页点「单会话」。
2. 首次跑会重新认一遍群/私聊，`data/chats.json` 会自动长出来。
3. 旧配置不用改：新增字段都有默认值。
4. 插件代码改动后需要**在插件页关/开一次**（热重载），不需要重启整个 DSH；配置改动写完即生效。

## 9. 已知限制

- 微信把无障碍树封了（`uiautomator dump` 只有一个空节点），所有"我在哪/点到谁"只能靠像素与 OCR。
- 识图描述不保证稳定，所以图片相关判断依赖"归一 + 看帧判官"，不是 100%。
- 群名过长时微信自己会截断，标题里的成员数可能读不到——靠 `data/chats.json` 兜。
- 主动搭话"找谁聊"由模型决定，偶尔会挑到你不想让它去的会话；用 `proactiveChats` / `proactiveDmBlacklist` 收窄。
